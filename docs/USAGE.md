# 使用教程

这份教程按「**第一次打开 → 日常使用 → 出问题怎么查**」的顺序写，
每一节都给出界面路径、对应接口与预期结果。想先跑起来看
[README 快速开始](../README.md#快速开始)；想知道每个参数为什么这样设计，
看 [ARCHITECTURE](ARCHITECTURE.md) 与 [DETECTION](DETECTION.md)。

> 约定：下文 `http://127.0.0.1:8000` 是默认本地地址；`/admin/` 是管理后台，
> `/` 是公网侧页面。管理接口只在 `local` 模式存在，`public` 模式下连路由都不注册。

## 一、第一次启动

### 1.1 三种运行方式

| 方式 | 命令 | 适合 |
| --- | --- | --- |
| 一键启动 | `launch.bat`（Windows）/ `launch.sh`（Linux·macOS） | 首次体验、日常使用 |
| 分步启动 | `powershell -File scripts/bootstrap.ps1` + `scripts/run.ps1 -BuildFrontend` | 想看清环境准备过程 |
| 独立可执行文件 | `dist/TrueSight.exe` / `dist/linux/TrueSight` | 目标机零环境 |

`launch.bat public 8010` 可临时切到公网只读模式并换端口；不带参数时读取仓库根目录
`truesight.config.json` 的 `server.mode / host / port`。

### 1.2 启动后先做三件事

1. 打开 <http://127.0.0.1:8000/healthz>，默认应返回
   `{"status":"ok","mode":"local","protection_level":2,"version":"1.1.5"}`
   （保护等级以「设置」页当前值为准）；
2. 打开 <http://127.0.0.1:8000/admin/>，左侧出现十个菜单：
   **总览 · 公告 · 名单 · 模型 · 服务 · 日志 · 设置 · 订阅 · 存储 · 检查**；
   左上角头像进入「我的」；
3. 打开 <http://127.0.0.1:8000/>，公网侧出现三个菜单：
   **仿冒态势 · 提交举报 · 拦截提示**。

### 1.3 登记第一个受保护资产

路径：管理后台 → **名单** → 「新增资产」折叠面板。

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 域名 | `example-brand.com` | 必填；自动成为白名单成员，`/api/v1/goto` 立即放行 |
| 展示名 | `示例品牌` | 用于界面与报告 |
| 关键词 | `示例, 示例品牌, 会员` | 逗号分隔；形近域名生成与内容匹配使用 |

等价的接口调用：

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/v1/admin/assets `
  -ContentType 'application/json; charset=utf-8' `
  -Body '{"value":"example-brand.com","label":"示例品牌","brand_keywords":["示例","示例品牌","会员"]}'
```

预期：条目出现在「受保护资产」表格；在下方「黑白名单 / 词典集」区域把类型筛选为
「白名单」，能看到 `source=protected_asset` 的只读合成行（说明它来自资产，不需要重复添加）。

## 二、公网侧怎么用

### 2.1 仿冒态势

- 顶部展示近 N 天识别总数、平均分、高风险占比与更新时间；
- 统计窗口支持 **7 / 30 / 90 天**（选择会被记住）；
- 风险等级、处置状态、仿冒意图为环形图，鼠标悬停单个扇区看具体数值与百分比；
- 页面可见时每 60 秒自动刷新，切换窗口立即重取；数据来自脱敏投影表，
  接口响应里的 `meta.desensitized=true` 就是在说明这一点。

接口：`GET /api/v1/dashboard?days=7`。

> 看板为空是正常的：只有出现过命中（扫描 / 举报 / goto 拦截）后才会有数据。
> 想马上看到效果，到「服务」页跑一次形近域名扫描（见 3.4）。

### 2.2 提交举报

路径：公网侧 → **提交举报**。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 被举报网址 | 是 | 完整 URL，必须 http/https |
| 补充说明 | 否 | ≤ 2000 字，例如「冒充某品牌登录页，要求输入账号与密码」 |
| 人机验证票据 | 否 | 保护等级较高时必需；先访问 `GET /api/v1/goto/challenge` 取挑战 |

受理结果有五种：`auto_verified`（初筛确认并落命中）、`pending_review`（转人工）、
`accepted`、`rejected`（举报自家资产或白名单）、`duplicate`（同域 30 分钟内重复提交）。

程序调用请务必带 `format=json`，否则接口会 302 到举报页：

```powershell
curl.exe -s "http://127.0.0.1:8000/api/v1/report?target=example-login.top&format=json"
```

### 2.3 拦截提示（外链中转）

把受保护站点的出站链接改写成：

```
https://protect.example.com/api/v1/goto?to=<URL 编码后的目标地址>&from=<来源页面>
```

保护等级 2–4 级对「风险等级中等及以上」的目标弹出确认页，
分别需要 1 / 2 / 3 次点击；5 级直接拦截，不提供继续按钮；0–1 级按各自策略放行或提示。
确认页的风险明细来自签名票据（`GET /api/v1/goto/inspect?ticket=…`），**不会重新评估**。
若提交失败（票据过期、网络抖动），直接再次点击确认按钮即可重试，无需重新打开原链接。

联调技巧：

- 加 `&format=json` 拿判定结果而不跳转；
- 不存在的域名会被 SSRF 策略按 fail-closed 拒绝，看到 `blocked_ssrf` 属预期；
- 未登记的域名会走真实检测（robots + 抓页 + TLS），受 `goto.decision_timeout_ms` 预算约束。

## 三、管理后台逐页说明

### 3.1 总览

- 计数、风险/状态/意图分布、任务健康度、证据占用；
- 环形图悬停查看数值；右上角「刷新」重新取数；
- `sequence` 用于页面顺序展示，不参与评分。

### 3.2 名单

页面分三块：**受保护资产**、**黑白名单**、**字典集**（独立卡片）。

| 操作 | 位置 | 注意 |
| --- | --- | --- |
| 新增资产 | 「新增资产」折叠面板 | 自动进白名单，立即生效 |
| 编辑资产 | 行内「编辑」 | 可改域名、展示名、关键词、启停、备注；改域名做唯一性校验 |
| 停用资产 | 行内「停用」 | 保留在册，随时恢复 |
| 删除资产 | 行内「删除」 | **二次确认**；同时移除白名单身份，审计保留删除前快照 |
| 新增/编辑/删除名单条目 | 「黑白名单」区域 | 白名单、黑名单两类；改值做同类别唯一性校验 |

白名单里 `source=protected_asset` 的行是只读的，维护入口在「受保护资产」。

**字典集**独立成卡片：可以逐行粘贴批量添加、勾选批量删除，或上传 `.txt/.csv/.json`
文件（先「预览」看新增/重复数量，再「导入」）。导入限 1MB、5000 条、单条 512 字符，
超限会明确拒绝而不是静默截断；所有动作写 `list.import` / `list.batch_*` 审计。

### 3.3 模型

- 供应商表格展示名称、地址、启停、优先级与**遮蔽后的密钥**（接口永不回明文/密文）；
- 「新增供应商」需要：名称、Base URL、API Key，可选分工模型与备注；
- 分工为五个下拉行（图像识别 / 源码分析 / 文本研判 / 报告生成 / 兜底分工），
  输入框会建议已用过的模型名，也允许手输；同一个模型可填到多个分工；
- 分工键：`VISION / SOURCE / TEXT / REPORT / GENERAL`，例如
  `REPORT=Qwen/Qwen2.5-7B-Instruct`；未知键会被丢弃，不会存成脏路由；
- 保存后点右上角「重新装配」才热切换路由；没有可用供应商时保持现状；
- 页面顶部的 `purpose_guide` 与 `guidance` 会直接说明缺哪个分工、哪些能力会降级。

> AI 只参与「可疑灰区复核」与报告生成：规则评分 35–59、有页面文本且未判高危时才调用，
> 最多 +20 分且**只升不降**。未配置模型不影响规则判定，只会在结果里留下降级说明。

### 3.4 服务

- 功能开关：中转判定、人工举报、态势看板、对外举报通道；关闭后对应接口返回
  `403 feature_disabled`（便于排查接入错误）；
- 能力健康：每个能力显示可用/降级/熔断与连续失败数；
- **立即执行一次任务**：选择任务类型后点击执行，同步返回执行结果与本轮命中列表。

| 任务类型 | 作用 |
| --- | --- |
| 形近域名扫描 | 按受保护资产关键词生成候选并评估 |
| 新注册域名监控 | 检查近期新注册的相关域名 |
| 历史命中重扫 | 对已有命中重新取页评估 |
| 取证补齐 | 对已确认命中补采证据 |
| 举报留痕（仅已确认命中） | 生成演练留痕，默认不对外发送 |

本轮成果可筛选、排序、分页；每条支持「打开网址 / 展开 / 确认仿冒 / 排除」。
结果会写入 `localStorage`，刷新后仍在，点「清除结果」一并移除记忆。

### 3.5 日志

顶部是命中区，两个视图：

* **命中记录**：待处理条目；`exclude_status=confirmed`，已确认的不会混在这里；
* **确认仿冒**：`status=confirmed`，只在这里出现。

行内操作与批量操作：

| 操作 | 范围 | 行为 |
| --- | --- | --- |
| 确认仿冒 | 单条 | 状态转 `confirmed`，默认生成一条演练举报留痕（不对外发送） |
| 排除仿冒 | 单条 | 状态转 `dismissed`，退回命中列表 |
| 处置 | 单条 | 只做取证与研判报告，不改变结论 |
| 清空命中 | 命中记录视图 | **二次确认**；只删除待处理记录及其证据，`confirmed/reported/resolved` 全部保留；提示「保留了 N 条已确认」 |
| 排除全部 | 确认仿冒视图 | **二次确认**；把尚未处理的确认记录退回命中列表（状态 `dismissed`），已处理的记录不会被批量撤回，需逐条撤销 |
| 确定处理 | 确认仿冒条目展开后 | **二次确认**；生成研判报告并写入一条演练举报留痕（不对外发送），记录处理时间与操作者；重复点击幂等，失败可重试 |

> 为什么清空不删确认记录：确认仿冒是已经定性、可能已经对外留痕的证据，
> 属于「结论」而不是「待办」。要退回它们请用「排除全部」，而不是清空。

下方四类日志：**举报投稿 / 举报留痕 / 后台任务 / 审计日志**（按此顺序排列）。均支持分页、筛选、关键字与导出：

- 举报投稿列表展示举报人填写的**补充说明**（过长时截断，悬停看全文）；
- 「只看待处理」默认开启：采纳/驳回后条目从工作列表移出，进入「确认仿冒」或保留为历史留痕；
- 采纳投稿时即使原先没有关联命中，系统也会按举报域名补建一条确认仿冒记录（来源=举报），
  不会出现「点了确认却找不到条目」；

- 导出格式 `csv / json`，单次 ≤ 10000 行；CSV 带 BOM 并防公式注入；
- 每次导出写 `log.export` 审计；
- 举报投稿可「确认仿冒 / 排除」；举报留痕默认是演练通道，需要人工确认后才走真实通道补发。

### 3.6 设置

八个分组卡片：**基础判定 / 服务开关 / 举报与验证 / 抓取与合规 / 周期任务 / 反滥用 /
AI 研判 / 界面显示**，每张卡片底部有独立的「重置本组 / 保存本组」。

- **本页不记忆未保存的输入**：切走再回来，草稿会重置为当前生效值。
  这是刻意设计——避免「改了输入框但没点保存，以为参数已生效」；
- 保存是**整组校验后统一落库**：任一项不合法则本组全部不生效，错误显示在字段下方；
- 标记「重启后生效」的参数（如抓取超时、限流额度）会明确提示，不假装立即生效；
- 周期任务间隔的单位是**秒**（下限 10 秒、上限 7 天）；五类任务默认间隔均为 **60 秒**，
  保存后调度器运行中会立即按新间隔重建任务，无需重启。秒级间隔会显著增加对外请求与
  存储写入，调整前先确认单轮上限。

「举报与验证」卡片里的两个相关项：

| 设置项 | 说明 |
| --- | --- |
| 启用常驻验证票据 | 默认关闭；开启后知道票据的人可跳过举报人机验证，仅建议受控渠道 |
| 常驻验证票据 | 密码框输入，可「显示/隐藏」或点「生成」得到 16 字节随机十六进制串；长度 8–128 字符，留空表示清除 |

保存票据后立即生效；审计只记录「已更新」，不回显值。

### 3.7 存储

- 展示数据目录总量与 `db / evidence / logs / runtime` 分项占用、磁盘余量、
  主要表行数与可清理目录清单；
- 「打开」调用系统文件管理器；无图形界面时返回 `opened=false` 与中文说明，不抛 500；
- 「清理」只允许 `logs / runtime`；被占用而删不掉的文件会计入失败并回显文件名。

数据库与证据目录不提供一键清理：要删证据请走「日志 → 确认仿冒 → 排除 / 清空命中」，
保证每次删除都有明确的业务语义与审计。

### 3.8 检查

主卡展示 Logo、服务端版本、发布阶段（当前为「正式版」）；从属卡展示运行模式、
保护等级、证据文件数、证据占用与界面覆盖设置数。下方是自检结论与升级说明，
页面每次进入都会重新自检，不缓存旧数字。

### 3.9 对外情报（给政企/监管）

在管理端 `POST /api/v1/admin/intel/clients` 创建调用方，保存响应里只出现一次的
`api_key`。之后用 `X-API-Key` 调用：

```powershell
curl.exe -s -H "X-API-Key: ts_xxx" `
  "http://127.0.0.1:8000/api/v1/open/findings/confirmed?limit=100"
```

- 两个 feed 默认互斥：`confirmed` 不含已处理，`processed` 只含已处理；
- 用响应里的 `next_cursor` 翻页，用 `ETag` + `If-None-Match` 做增量轮询；
- Key 停用后立即失效，历史审计仍保留；
- 对外只给仿冒目标本身，不含举报人、租户、备注与证据文件路径。

## 四、常见任务速查

```powershell
# 1) 查看命中（待处理）
curl.exe -s "http://127.0.0.1:8000/api/v1/admin/findings?limit=5"

# 2) 查看确认仿冒
curl.exe -s "http://127.0.0.1:8000/api/v1/admin/findings?status=confirmed"

# 3) 确认一条命中（会生成演练留痕）
curl.exe -s -X POST "http://127.0.0.1:8000/api/v1/admin/findings/1/review" `
  -H "Content-Type: application/json" -d "{\"decision\":\"confirmed\"}"

# 4) 清空待处理命中（保留已确认）
curl.exe -s -X DELETE "http://127.0.0.1:8000/api/v1/admin/findings?confirm=true"

# 5) 批量排除全部（退回命中列表）
curl.exe -s -X POST "http://127.0.0.1:8000/api/v1/admin/findings/exclude-confirmed?confirm=true"

# 6) 导出最近 7 天审计（CSV）
curl.exe -s -o audit.csv "http://127.0.0.1:8000/api/v1/admin/logs/audit/export?days=7&format=csv"

# 7) 手动跑一次形近域名扫描
curl.exe -s -X POST "http://127.0.0.1:8000/api/v1/admin/tasks/run" `
  -H "Content-Type: application/json" -d "{\"kind\":\"typosquat_scan\"}"
```

> PowerShell 5.1 下 `curl.exe -d '{"a":1}'` 的引号容易被吞掉，
> 含 JSON 的请求建议用 `Invoke-RestMethod`（见 1.3）。

## 五、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `/api/v1/goto` 返回 `blocked_ssrf` | 域名解析失败或不存在的域名，按 fail-closed 拒绝 | 换真实可达的域名联调 |
| 页面 404 | 前端还没构建 | `powershell -File scripts/run.ps1 -BuildFrontend` |
| 管理接口 404 | 当前是 `public` 模式 | 用 `local` 模式启动；公网模式不挂管理路由 |
| `feature_disabled` | 对应功能在「服务」页被关闭 | 打开开关后重试 |
| 静态资源 404 | 浏览的是旧指纹文件 | 硬刷新页面；入口页已禁用缓存 |
| 前端构建报 `Cannot find module @rollup/rollup-*` | Windows 与 WSL 共用了 `node_modules` | 重新运行 `launch` / `verify`，脚本会自动重建依赖 |
| 判定结果是 `indeterminate` | 时间预算内没完成检测 | 适度调大 `goto.decision_timeout_ms`；属分级降级 |
| AI 结论缺失 / 报告是模板 | 模型未配置、缺分工或超时 | 在「模型」页配置并「重新装配」；降级原因会在条目里写明 |

更多「如何演示」「这些是明确降级还是没做」见 [FAQ](FAQ.md)。

## 六、数据、备份与升级

| 内容 | 位置（源码运行） | 位置（独立可执行文件） |
| --- | --- | --- |
| 数据库 | `data/db/` | 可执行文件旁 `data/db/` |
| 证据 | `data/evidence/` | 可执行文件旁 `data/evidence/` |
| 运行日志 | `data/logs/` | 可执行文件旁 `data/logs/` |
| 配置 | `server/.env` + 根目录 `truesight.config.json` | 可执行文件旁的 `.env` + `truesight.config.json` |

- 升级前备份数据库文件与证据目录；
- 替换可执行文件不会动 `data/`、`.env` 与 `truesight.config.json`；
- 启动时自动幂等补齐模型新增的可空列与索引，非空列补齐全跳过并输出警告，
  不需要手工执行迁移脚本；
- 主密钥（`TRUESIGHT_SECRET_KEY`）变更后，已加密保存的模型密钥将无法解密，
  需要重新录入；占用位密钥会在启动日志与「服务」页给出中英双语告警。

更完整的部署与安全加固见 [DEPLOYMENT](DEPLOYMENT.md) 与 [HARDENING](HARDENING.md)。

## 七、二期新增：登录、订阅与 A 端

### 7.1 第一次登录管理后台

内部构建启动后打开 `/admin`，页面会检查登录状态：

1. 如果系统还没有任何账号且注册开放，页面默认停在「注册」标签：填写用户名、密码
   （至少 10 位，不能包含用户名）、邮箱与手机号验证码，提交后自动创建组织并登录；
2. 登录、注册、找回密码共用**同一张卡片**，顶部标签直接切换；管理后台不再提供
   「初始化」入口，已有账号时默认停在「登录」；
3. 登录后左下角显示当前账号与组织，点「退出登录」结束会话；点左上角头像进入「我的」。

**登录**：主表单只需「用户名 / 邮箱 / 手机号」与密码；如果同一个用户名分布在多个组织，
点中间的灰色箭头展开「组织标识」，填写后即可精确定位。

**注册**：主表单填写用户名、密码、邮箱、邮箱验证码、手机号、手机验证码；两个验证码分别
点「获取验证码」。组织名称、组织标识与邀请码收在灰色箭头后：留空时组织标识由用户名派生、
组织名称默认为「无组织」，之后可在「我的」里修改。注册默认开启，成功后自动创建租户、
owner 与测试套餐。

**忘记密码**：填写用户名（也可填邮箱或手机号）、组织标识（单机部署可留空），选择
「邮箱」或「手机号」，填写账号绑定的联系方式后点「获取验证码」，再填写验证码与新密码。
当前默认是演示模式（`TRUESIGHT_AUTH__VERIFICATION_MODE=stub` 且测试模式开启）：
不会真的发信/发短信，验证码任意填写都能通过，页面会明确提示「演示模式：不会真正发送」；
接入邮件或短信渠道并切换为 `strict` 后才会真实校验。A 端关闭测试模式后，即使配置仍是
`stub` 也会强制校验验证码；如果发送渠道未配置，页面会提示「验证码未能发送，请联系管理员」。
重置成功后其他设备的会话全部下线。

注意：

* 默认一个账号只允许一台设备在线，换设备登录会把旧设备踢下线（A 端可按租户调整）；
* 连续输错 5 次会临时锁定 15 分钟；错误提示不会告诉你「用户名是否存在」；
* 企业交付包（business）**不展示网页初始化入口**，由服务方预置账号后再交付；
  自助注册是否开放仍由 `TRUESIGHT_AUTH__ALLOW_REGISTRATION` 控制。

### 7.2 「我的」个人资料

点击左上角头像进入：

* 资料卡主标题显示登录用户名，副标题显示「组织名称 · 用户名（昵称）」；
* 修改昵称（只影响显示，不改变登录用户名）；
* **点击资料卡头像**即可上传新头像（浏览器先压缩到 160×160；支持 PNG/JPEG/WEBP）；
  「恢复默认头像」在头像行右侧；
* 修改邮箱与手机号需要分别填写发送到新目标的验证码；两者都可用于登录与找回密码；
* 所有者可修改组织名称；
* 修改密码后，其他设备会被强制下线；
* **注销账号**：填写当前密码并确认后删除账号，所有会话立即失效、页面回到登录界面；
  组织最后一名所有者需先转让所有权，避免组织失去管理入口。

### 7.3 订阅页

管理后台左侧「订阅」：

* 「当前权益」显示套餐、月价、已用/上限资产数、到期时间与来源；时间统一显示为
  「2026-12-11 16:32」这样的本地时间，不再直接展示 ISO 字符串；
* 套餐卡片显示月价、说明与特权清单（由 `/root/` 设置），便于对比后再开通；
* 选择 30 / 90 / 365 天后，套餐卡片价格按所选周期显示为月价 / 季价 / 年价；
  点击卡片会高亮选中，再点「开通」即可续期或切换；
* 同名套餐续费在原订阅上延长到期时间，连续点两次「开通」仍保持当前套餐，
  不会掉回免费版；切换套餐会立即替换旧订阅；
* 选中套餐后，卡片下方显示**应付金额**：升级时按旧套餐剩余月数抵扣
  （如剩余 2 个月 VIP 升级 SVIP，买 1 个月应付 ¥100），同套餐续费与降级按原价；
* 「取消当前订阅」会立即回落到组织的默认套餐（通常为免费版）；
* 本期**不接支付**：页面不扣费，只开通权益；真实收款由线下/外部流程完成。
* 订阅记录的「开始 / 结束」同样按本地时间显示，排错时不需要自己换算时区。
* 当前为**正式服务**时（A 端关闭测试模式），套餐卡片与「取消当前订阅」按钮会禁用，
  页面提示联系平台运营；这是为了避免在没有支付与对账的情况下免费获得付费套餐。

当受保护资产达到套餐上限时，新增资产会返回「配额已用完」，需要升级套餐或联系服务方。

### 7.4 公告

公告由 **A 端 `/root/` 发布、B 端 `/admin/` 接收**。企业端左侧「公告」页列出全部生效公告：
标题、类型与日期为主信息，正文默认收起，点击条目展开（正文最高 40vh，超出可滚动）；
切换页面时立即刷新，停留在同一页时每 60 秒拉取一次。只显示**已发布且已生效**的公告，
草稿与未来生效的公告不会提前出现。

顶部公告横幅只提示**尚未读过的新公告**：

* 一次只显示一条，标题单行、正文最多两行，整体限高，不会挤占首屏；
* 每条停留 15 秒后自动消失；点右侧「×」可立即关闭；
* 多条新公告按生效时间从新到旧依次出现；
* 已读记录保存在浏览器本地，刷新或重新登录不会重复弹出；退出登录会清空待展示队列。

### 7.5 A 端平台控制台（仅内部构建）

1. 首次启动默认创建平台管理员 `root / 123456`，启动横幅会同时打印
   `平台控制台：http://127.0.0.1:8000/root/`；已有平台账号时不会覆盖密码；
2. 需要自定义初始账号时，在 `.env` 配置
   `TRUESIGHT_PLATFORM__BOOTSTRAP_USERNAME` 与 `TRUESIGHT_PLATFORM__BOOTSTRAP_PASSWORD`；
3. 可查看总览（含套餐、租户与成员分布环形图）、管理租户（停用/启用、开通、配额、成员）、
   调整套餐权益（含月价与特权）、发布公告；平台租户内的账号统一拥有完整权限；
4. 点击左上角 Logo 会轻微跳动并回到总览，与 `/admin/` 的交互一致。

平台账号属于独立的 `platform` 租户，与企业管理账号完全隔离；企业账号在 `/root`
无法登录。默认密码仅用于首次登录，登录后请立即在「我的」中修改。

### 7.6 A 端「设置」：测试服务与正式服务

左侧「设置」页用于区分演示与正式交付：

* **默认开启测试模式**：只在当前模式尚未被手动设置时生效，作为新部署的初始形态；
* **开启测试模式**：当前实际形态，切换后立即生效，重启后从数据库恢复；
  从测试服务切到正式服务前会弹窗确认，避免误触；
* 页面顶部显示当前形态（测试服务 / 正式服务）、来源（部署默认值 / 手动设置）与
  实际验证码模式（stub / strict）；读取失败时只影响本页，并可点「重试」；
* 开启测试模式时：B 端可免费开通/升降级、stub 验证码任意通过、新注册赠送 365 天 SVIP；
* 关闭测试模式后：B 端自助开通、续期、降级与取消全部拒绝；验证码强制 strict；
  新注册租户不再赠送测试套餐，停在免费版。

如果关闭测试模式时部署仍配置为 stub，页面会出现醒目告警：此时没有真实发送渠道，
注册与找回将无法完成，需先配置 `TRUESIGHT_AUTH__VERIFICATION_MODE=strict` 并接入
邮件/短信发送。详细规则见 [PLATFORM](PLATFORM.md#45-测试模式与正式服务)。

### 7.7 打包企业版与内部版

```powershell
# 企业交付包：只有 / 与 /admin
powershell -File scripts/build-exe.ps1 -Edition business

# 自留 B+A 包（默认）
powershell -File scripts/build-exe.ps1 -Edition internal
```

```bash
bash scripts/build-elf.sh --edition business
bash scripts/build-elf.sh --edition internal
```

版本的隔离发生在构建期：企业包不带 `/root` 前端，PyInstaller 也会排除平台模块；
即使目标机器改写环境变量，也不会出现平台入口。

### 7.8 依赖同步（uv）

```powershell
winget install astral-sh.uv          # 或 pip install uv
powershell -File scripts/uv-sync.ps1           # 同步开发依赖
powershell -File scripts/uv-sync.ps1 -Frozen   # 严格按 uv.lock（CI/交付）
```

首次仍需 `scripts/bootstrap.ps1` 生成 `.env`；其余场景 `uv sync` 更快且可复现。

更多细节见 [PLATFORM](PLATFORM.md)。
