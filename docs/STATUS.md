# 项目现状、能力边界与改进清单

> 快照时间：2026-11-17 · 版本 `1.1.5` · 后端 **1352 项测试**全绿。
> 这篇文档回答三个问题：**现在有什么、哪些只是条件可用、哪些明确没做**。

## 一、一句话现状

TrueSight 已经是一条可运行、可解释、可降级的本地流水线：
**外链拦截 / 周期扫描 / 人工举报 → 域名/内容/证书/备案分析 → 评分与意图 →
命中落库 → 证据与报告 → 人工确认 → 演练/上报留痕 → 脱敏态势**。
它不是一个「万能安全网关」，而是一个**可演示、可审计、可被替换**的仿冒检测防护组件。

## 二、已实现（默认可用）

| 领域 | 能力 | 入口 / 证据 | 边界 |
| --- | --- | --- | --- |
| 出站判定 | `GET /api/v1/goto` 放行 / 确认页 / 拦截 / JSON 裁决 | [API](API.md#1-出站跳转中转-get-apiv1goto) | 依赖目标站点可达；受 2500ms 预算约束 |
| 安全 | CSP/安全响应头、SSRF 逐跳、签名票据、限流、人机验证、受信代理、登录/会话/CSRF | [SECURITY-ARCHITECTURE](SECURITY-ARCHITECTURE.md)、[PLATFORM](PLATFORM.md) | 租户角色已落地；检测数据表尚未全量按租户隔离 |
| 域名层 | 形近候选生成、可疑度筛查、新域监控框架 | `app/engine/dga/` | 候选生成有上限；不是全量 DNS 测绘 |
| 内容层 | robots 遵从、逐跳 SSRF、体积上限、文本语义 | `app/engine/crawler/`、`analyzers/text_semantic.py` | robots 禁止时明确跳过 |
| 证书/备案 | TLS 证书特征；ICP 查询接口 | `analyzers/ssl_icp.py` | ICP 默认无 provider，明确降级 |
| 评分 | 分层加权 + 策略下限 + 风险等级/意图 | `engine/scoring/` | 权重是标定值，需真实样本持续校准 |
| AI | 可疑灰区复核（35–59 分，最多 +20，只升不降）；报告生成 | `engine/judgement.py`、`engine/reporting/` | 未配置模型时明确降级，不伪造结论 |
| 命中 | 可注册域去重、状态机、审核、任务成果 | `services/findings.py`、`services/admin.py` | 单机 SQLite；检测数据仍是共享表，未做多企业隔离 |
| 账号 | 租户/成员、scrypt 密码、会话、单设备、锁定、CSRF、邮箱/手机号登录、注册双验证码、联系方式修改验证、注销账号 | `services/accounts.py`、`services/verification.py`、`api/local/auth.py` | 企业构建强制登录；真实邮件/短信发送渠道仍需部署方接入 |
| 订阅 | 免费/VIP/SVIP（¥99 / ¥199）、月价与特权清单、权益版本按生效时间、租户覆盖、资产配额、升级按剩余月数抵扣 | `services/plans.py`、`api/local/subscription.py` | 未接支付；正式服务下 B 端自助开通/降级关闭，由 A 端手工开通 |
| 服务形态 | A 端「设置」切换测试模式与正式服务；默认值/当前值分离、持久化、重启恢复 | `services/test_mode.py`、`api/platform/root.py`、`frontend/apps/root-console` | 单进程内存缓存；多实例需额外广播机制 |
| A 端 | `/root` 平台总览（含套餐/租户/成员分布环形图）、租户/成员/权益/公告管理；平台账号统一拥有完整权限 | `services/platform.py`、`api/platform/root.py` | 仅 `internal` 构建；平台账号独立租户 |
| 公告 | 全体/指定租户、草稿、预约生效 | `services/announcements.py`、`api/local/announcements.py` | 只在 B 端管理后台展示，无邮件/短信 |
| 证据 | SHA-256、清单、自校验、证据索引与下载 | `engine/forensics/`、`services/evidence.py` | 本地文件；没有第三方时间戳/公证 |
| 处置 | 确认仿冒、排除、批量退回确认记录、取证与报告、举报留痕 | `services/disposition.py`、`services/abuse.py`、`services/admin.py` | 默认 `dry_run`，不自动对外发送 |
| 举报 | 人工举报受理、初筛、审核、关联命中 | `services/report.py` | 受保护资产/白名单直接拒绝 |
| 调度 | 5 类任务（形近扫描/新域监控/重扫/取证/留痕） | `scheduler/` | **默认关闭**；需管理员开启 |
| 看板 | 脱敏投影、聚合统计、趋势、自动回填 | `services/dashboard.py`、`services/findings.py` | 公网只看投影，不含原始证据 |
| 管理后台 | 总览 / 公告 / 名单 / 模型 / 服务 / 日志 / 设置 / 订阅 / 存储 / 检查，以及头像入口「我的」；公告横幅只提示未读新公告，15 秒自动消失且可关闭 | `frontend/apps/admin-console` | 只在 `local` 模式挂载；登录/注册/找回共用一张卡片，无初始化入口 |
| A 端前端 | 平台总览（含分布环形图）/ 租户 / 套餐 / 公告 / 设置 / 我的 | `frontend/apps/root-console` | 只在 `internal` 构建打包 |
| 公网前端 | 仿冒态势 / 提交举报 / 拦截提示；侧栏可拉伸 | `frontend/apps/web-client` | 无管理接口 |
| 站点配置 | 根目录 `truesight.config.json`：Logo/Favicon、端口、公网、Host、默认窗口 | `app/core/site_config.py` | 修改后需重启 |
| 分发 | Windows `TrueSight.exe`；Linux `TrueSight` ELF | `scripts/build-exe.ps1`、`build-elf.sh` | 不能跨平台交叉编译 |

## 三、条件可用（需要配置或注入依赖）

这些能力代码在、路径在，但**默认不会真的产生外部效果**；界面与日志会说明原因。

| 能力 | 需要什么 | 缺省表现 |
| --- | --- | --- |
| 威胁情报 | 注入 `ThreatIntelProvider` | `skipped`：「未配置威胁情报源」 |
| 新域监控 | 提供 `DomainFeed`（仓库内置 `StaticDomainFeed` 仅演示） | 任务可跑，但没有真实注册局数据源 |
| ICP 备案 | `HttpIcpProvider` 与查询端点 | `skipped`：「未配置 ICP 备案查询服务」 |
| AI 研判 / 报告 | 管理后台配置文本/报告模型 | 规则报告兜底；灰区只按规则评分 |
| 对外举报 | `webhook` 端点 + **人工确认** | 默认 `dry_run`，只生成请求体与留痕 |
| 周期扫描 | 管理后台「服务」页开启调度 | 默认关闭，避免装完就扫描别人站点 |
| 视觉相似度 | 目前只有能力位与降级说明 | 明确记为未接入，不伪造结果 |
| RDAP/WHOIS、DNS | 目前只有能力位与降级说明 | 明确记为未接入，不伪造结果 |

> 「条件可用」不是偷懒：外部依赖失败或未配置时，**系统仍然给出结论**，
> 只是把缺失的那一层写进 `skipped_capabilities` / 中文说明。这是本项目的核心设计。

## 四、明确未实现 / 非目标

* **不是 WAF / 反向代理**：只裁决「用户点击外链」这一刻，不接管站点全部流量；
* **不是自动取证机器人**：证据采集基于一次页面抓取与结构化快照，不做长期监测；
* **不是自动删除/下架系统**：对外举报默认演练，真实提交需人工确认；
* **不做支付/发票/退款**：订阅页只开通权益，真实收款由外部流程完成，界面不假装扣费；
* **检测数据未全量租户隔离**：账号、会话、设置、订阅与公告已按租户隔离；
  命中、资产、名单仍是单库共享表，托管多企业隔离需要继续给这些表加 `tenant_id`
  并强制作用域（见 [PLATFORM](PLATFORM.md#八明确边界未实现--降级)）；
* **不做云端水平扩展**：SQLite + 单进程是刻意选择，横向扩展需换 PostgreSQL 与任务队列；
  配额锁目前是进程内锁，多实例需要数据库行锁或唯一约束兜底；
* **不做浏览器插件**：当前以中转链接方式接入，避免维护多浏览器扩展；
* **不做真实注册局全量数据**：新域监控是框架 + 可注入数据源，不是全量 `.com` 扫描器；
* **不做第三方时间戳/公证**：证据清单可自校验，但不具备法律意义上的第三方存证。

## 五、看得见与看不见的边界

**用户能看见**：拦截中间页、举报结果、仿冒态势看板、任务执行结果、命中详情、证据与报告、降级说明。

**用户看不见**：
保护等级能力计划、熔断与兜底链、SSRF 逐跳校验、robots 判定、限流与人机验证、
评分因子合成、AI 灰区门控、命中去重、投影同步、审计日志、调度器触发器。

完整链路见 [FLOWS.md](FLOWS.md)，算法细节见 [ALGORITHMS.md](ALGORITHMS.md)。

## 六、已知不足

1. **标定样本有限**：权重与阈值来自方案推演与小规模演示，缺少大规模真实仿冒样本的 ROC/PR 校准；
2. **域名层强、内容层受网络影响大**：目标站点不可达时只能退到域名/情报证据；
3. **AI 只做加分**：能降低「伪装较好的站点」漏判，但不能推翻规则高危结论（这是有意的安全取舍）；
4. **单机 SQLite**：命中量到十万级后需要归档策略或迁移 PostgreSQL；
5. **无真实新域/情报数据源**：框架已留好接口，但默认演示数据无法代表生产覆盖率；
6. **视觉相似度未接入**：仿冒页面截图比对仍是能力位；
7. **前端无自动化 E2E**：目前依赖构建 + 浏览器手工验收，缺少 Playwright/Cypress 回归；
8. **打包体积较大**：PyInstaller onefile 约 35 MB（Linux），首次启动需解压；
9. **无国际化**：界面与文档以中文为主，英文只保留关键术语与告警。

## 七、建议的改进优先级

| 优先级 | 改进 | 价值 |
| --- | --- | --- |
| P0 | 用真实样本校准评分权重与阈值，输出混淆矩阵 | 直接决定误报/漏报 |
| P0 | 接入真实新域数据源（RDAP/注册局/证书透明日志） | 把「新域监控」从演示变成能力 |
| P1 | 视觉相似度（截图 + 感知哈希/多模态） | 补上「页面长得像」这一层证据 |
| P1 | 证据第三方时间戳（可选） | 提升维权附件可信度 |
| P1 | Playwright 端到端回归 | 防止前端改动回归 |
| P2 | PostgreSQL + 任务队列 | 多实例与更大数据量 |
| P2 | RBAC / 审计导出 | 多人协作场景 |
| P2 | 打包体积优化（onedir / 裁剪依赖） | 分发体验 |

> 这份清单不是承诺，而是**当前代码与真实生产之间还差什么**的诚实记录。
