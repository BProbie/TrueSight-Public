# 租户、账号、订阅与 A 端平台

这份文档讲清二期新增的「谁在用、能用多少、谁能管」三件事：

1. **租户与账号** —— 企业（租户）里有哪些角色，怎么登录、怎么下线；
2. **订阅与权益** —— 套餐怎么定义、权益怎么按时间生效、配额怎么拦截；
3. **A 端平台** —— 服务方自己的控制台做什么、为什么企业拿不到它。

> 现状边界写在最后：「已实现」与「明确未实现」分开列，避免把规划当能力。

---

## 一、三个入口，三种身份

| 入口 | 使用者 | 身份 | 说明 |
| --- | --- | --- | --- |
| `/` | 企业客户 | 匿名访客 | 仿冒态势、提交举报、拦截提示 |
| `/admin` | 企业管理员/分析员 | 租户成员 | 检测、名单、日志、设置、订阅 |
| `/root` | 服务方运营 | 平台租户成员 | 管理所有企业、套餐与公告（仅 internal 构建） |

两类身份**在数据与会话上都隔离**：

* 企业会话 Cookie 名为 `ts_session`（`Path=/`）；
* 平台会话 Cookie 名为 `ts_root_session`（`Path=/root`）；
* 平台接口还要求主体属于 `platform` 租户，企业账号即使在数据库里被误改角色，
  也无法通过平台接口的租户校验。

## 二、数据模型

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| `tenants` | 企业/平台边界 | `slug` 唯一；`status`（active / pending / suspended） |
| `users` | 成员账号 | 密码只存 scrypt 派生值；`(tenant_id, username)` 唯一 |
| `auth_sessions` | 登录会话 | 只存令牌 SHA-256；绑定 CSRF 令牌与客户端指纹 |
| `plans` | 套餐展示信息 | `code` 稳定；`level` 决定权益优先级 |
| `plan_versions` | 权益版本 | `(plan_code, effective_from)` 唯一；到点自动生效 |
| `subscriptions` | 租户订阅 | 是否生效完全由时间判定，不依赖定时任务 |
| `tenant_overrides` | 租户级例外 | 目前支持 `quota.assets`；同样带生效时间 |
| `announcements` | 平台公告 | 已发布 + 已生效才出现在 B 端 |

为什么订阅不做「状态字段翻转」：进程停摆、时钟漂移或多实例竞争都可能让状态与时间脱节。
「是否生效 = `starts_at <= now < expires_at` 且未取消」是唯一事实来源，永远不会出现
「过期还能用」。

## 三、登录、会话与 CSRF

### 3.1 密码与锁定

* scrypt（N=2^14, r=8, p=1），每条记录独立随机盐；参数写入哈希串，未来提高强度后
  登录成功会静默重算，不打扰用户；
* 密码至少 10 位、不能包含用户名、拒绝常见弱口令片段；
* 连续失败达到阈值即锁定（默认 5 次 / 15 分钟），计数落库、重启不清零；
* 登录接口按客户端指纹限流（默认 10 次/分钟，突发 5），是防爆破的第一道；
* 「用户不存在」与「密码错误」返回同一个 `auth_failed`，并做等时比较，避免账号枚举。

### 3.2 会话与单设备

* 令牌 32 字节随机数，Cookie 为 HttpOnly + SameSite=Lax，HTTPS 部署自动 Secure；
* 绝对有效期默认 12 小时，空闲超时默认 2 小时；
* 单账号默认只允许 **1 个活跃会话**；新登录会撤销超出的旧会话。A 端可按租户覆盖；
* 修改/重置密码会撤销除当前会话外的全部会话；停用账号立即失效。

### 3.3 CSRF

登录/状态接口返回 `user.csrf_token`，前端写入内存并在写请求带 `X-CSRF-Token`。
服务端要求它与会话中的令牌常量时间相等。跨站表单读不到该请求头，因此即使浏览器
自动带上 Cookie，也构造不出成功的写请求。

### 3.4 首次使用、注册与找回密码

* 管理后台**不再展示初始化入口**：首次打开 `/admin` 且没有任何账号时，若注册开放，
  直接停在「注册」标签；登录、注册、找回密码共用一张卡片；
* 后端仍保留 `POST /api/v1/auth/setup`，供部署脚本或受控初始化使用（只允许无账号时
  执行一次）；企业构建默认 `setup_allowed=false`，需要时临时设置
  `TRUESIGHT_AUTH__ALLOW_BOOTSTRAP=true`，初始化后立即改回；
* 企业注册：登录页可注册新租户；默认开启（`auth.allow_registration`），受可选邀请码
  控制，按客户端指纹限流，测试模式下注册成功获得测试套餐。注册必须填写邮箱与手机号并
  分别通过验证码；两者在 **B 端账号空间内唯一**（A 端是独立空间，可重复），注册后可直接
  用于登录。组织名称留空为「无组织」，组织标识留空由用户名派生；
* **忘记密码走邮箱/手机验证码**：前端调用 `/api/v1/auth/verification` 获取验证码，
  再调用 `/api/v1/auth/recover` 重置密码。测试模式开启且配置为 `stub` 时——只要邮箱/手机
  格式合法，任意验证码通过；配置 `TRUESIGHT_AUTH__VERIFICATION_MODE=strict` 并接入发送
  渠道后才做哈希、有效期与尝试次数校验。A 端关闭测试模式后会强制走 strict（见 4.5）。
  重置成功会撤销全部会话；
* **登录标识**：用户名、邮箱、手机号都可作为登录名；同名账号分布在多个租户时，
  登录页展开「组织标识」指定租户；
* 平台管理员不走网页初始化：由 `TRUESIGHT_PLATFORM__BOOTSTRAP_USERNAME/PASSWORD`
  在启动时幂等创建。

### 3.5 个人资料

点击管理后台左上角头像进入「我的」（不占侧栏菜单）：

* 昵称与登录用户名分离，可自由修改；昵称保存失效的根因是共享 API 客户端缺少
  `PATCH` 方法，已补齐；
* 点击资料卡头像即可上传（前端压缩为 160×160，后端只接受 PNG/JPEG/WEBP data URL
  并限制体积），「恢复默认头像」位于头像行右侧；
* 邮箱与手机号用于登录与找回密码，不会公开展示；修改时必须提供发送到新目标的验证码，
  且在 B 端账号空间内唯一（A 端平台账号互不影响）；
* 所有者可修改组织名称；
* 修改密码后，除当前会话外的其他设备立即下线；
* 注销账号需再次校验当前密码，成功后撤销全部会话；组织最后一名所有者会被拒绝，
  必须先转让所有权。

### 3.6 A 端注册与权限来源

A 端是内部运营控制台：登录平台租户即拥有完整权限，不再区分只读分析员与所有者。

1. 路由只在 `internal` 构建 + `local` 模式存在；
2. 登录只接受 `platform` 租户成员，并使用独立 Cookie；
3. 自助注册默认开启（`platform.allow_registration`），新账号直接创建为 `OWNER`；
   启动时会把历史 `ANALYST` 账号幂等提升为 `OWNER`；注册必须填写邮箱/手机号并分别
   通过验证码；联系方式唯一性只在 A 端账号空间内生效，与企业端完全独立；若配置了
   `TRUESIGHT_PLATFORM__REGISTRATION_TOKEN`，注册还必须携带令牌；
4. 写操作要求平台登录 + 平台 CSRF；默认初始账号为 `root / 123456`，已有平台账号时
   不会覆盖密码，登录后应立即修改；
5. 需要完全关闭注册时，设置 `TRUESIGHT_PLATFORM__ALLOW_REGISTRATION=false`。

## 四、订阅、权益版本与配额

### 4.1 默认套餐

| 套餐 | 资产上限 | 月价（元） | 默认特权 |
| --- | --- | --- | --- |
| `free` | 10 | 0 | 基础域名与内容检测、人工举报通道 |
| `vip` | 100 | 99 | 完整检测与处置能力、AI 研判报告 |
| `svip` | 500 | 199 | 优先检测与处置、定制化研判报告 |
| `internal` | 不限（-1） | 0 | 本地化部署、内部运营支持 |

月价与特权存放在 `PlanVersion.features`（`price_monthly`、`privileges`），A 端可随配额
一起按版本调整；B 端订阅页直接读取当前生效版本，因此「卖什么、多少钱」只有一处事实来源。
旧库升级时若 `features` 为空，会在启动时补上默认值。

时长按方案支持 1 小时、1/3/7/30/90/365 天；订阅界面默认展示 30/90/365 天，
套餐卡片价格会按所选周期折算为月价 / 季价 / 年价。

**升级抵扣**：仅当目标套餐等级高于当前套餐时，才按旧套餐剩余时长抵扣。
计费月按 30 天折算，剩余时间向上取整（刚开通 60 天、过几秒仍算 2 个月），
抵扣月数取「剩余月数」与「本次购买月数」的较小值，避免抵扣超过本次购买量：

```
应付金额 = 新套餐月价 × 购买月数 − 旧套餐月价 × min(旧套餐剩余月数, 购买月数)
```

例如剩余 2 个月 VIP（¥99/月）升级 SVIP（¥199/月）：买 1 个月应付 `199 − 99 = 100`；
买 3 个月应付 `597 − 198 = 399`。同套餐续费与降级不抵扣，按原价计算。
应付金额由后端 `quote_upgrade` 统一计算（`GET /api/v1/admin/subscription/quote`），
前端只展示，不参与定价。

### 4.2 权益变更为什么用「版本」

A 端改权益时可以设置生效时间。如果直接改套餐行，历史订单与已售权益会被追溯改写；
因此每次变更写一条 `plan_versions`：

* 当前权益 = `effective_from <= now` 的最新版本；
* 未来版本不会提前出现在 B 端订阅界面；
* 不需要定时任务，到点自然生效；
* 历史版本保留，可解释「当时卖的是什么」。

### 4.3 优先级

```
租户覆盖（tenant_overrides，已生效）
  > 生效中的订阅（取等级最高者）
    > 租户默认套餐（tenants.plan_code）
      > 免费版
```

### 4.4 配额如何拦截

新增受保护资产时，在**同一个事务**内统计当前数量并校验上限。SQLite 默认隔离级别下
「先查后写」仍有并发窗口，因此单进程部署用一把进程内锁串行化该临界区。
多实例部署需要数据库行锁或唯一约束兜底 —— 这一点明确写在代码注释里，不做
「假装多实例也安全」的承诺。

### 4.5 测试模式与正式服务

演示环境与正式交付共用同一套代码，如果不加区分，就会出现「VIP 可以免费开通、
SVIP 可以随手降级、验证码随便填」这类只适合测试的行为。A 端「设置」页因此提供
两个开关（`GET/PATCH /root/api/v1/platform/settings/test-mode`）：

| 设置 | 库内键 | 作用 |
| --- | --- | --- |
| 默认开启测试模式 | `platform.test_mode_default` | 仅在**当前模式尚未被显式设置**时作为初始值；新部署默认开启 |
| 开启测试模式 | `platform.test_mode` | 当前实际形态；一旦手动切换，就以它为准 |

「默认值」与「当前值」分开的原因：改默认值不应该偷偷覆盖运营人员已经做出的正式/测试
决定。界面上会显示当前模式的来源（部署默认值 / 手动设置）。

**测试模式开启（默认）**

* B 端可自助开通、续期、升降级套餐，直接生效（本期不接在线支付）；
* `auth.verification_mode=stub` 时任意验证码通过；
* 新注册租户自动获得 365 天 SVIP 测试权益。

**正式服务（测试模式关闭）**

* B 端自助开通、续期、降级与取消全部返回 403 `feature_disabled`，提示联系平台运营；
  A 端仍可为租户手工开通（来源 `platform`），用于线下合同/对账；
* 验证码强制按 `strict` 校验，即使部署配置仍是 `stub`；
* 新注册租户停在免费版，不再赠送 SVIP 测试权益。

**验证码的边界**：正式服务只保证「不再放行任意验证码」，并不等于「已经能发验证码」。
如果部署仍是 `stub` 且没有接入邮件/短信发送渠道，注册与找回会因为收不到真实验证码
而无法完成。A 端设置页会在这个组合下给出醒目告警，启动日志也会打印同样的提示；
生产部署必须配置 `TRUESIGHT_AUTH__VERIFICATION_MODE=strict` 并注入真实发送渠道（见
[HARDENING.md](HARDENING.md)）。前端请求验证码时会区分三种结果：stub 明确提示不会发送、
strict 已送达提示查收、strict 未送达提示联系管理员，不会再把「没发出去」显示成「已发送」。

状态缓存在进程内：A 端切换后立即对当前进程生效，重启时由
`ServiceModeService.load()` 从 `settings` 表恢复；本项目按单进程部署设计，
多实例部署需要额外的配置广播机制（当前明确不支持）。

## 五、A 端平台

### 5.1 能做什么

* 总览：租户/成员/生效订阅/生效公告数量，以及套餐分布、租户状态、成员状态环形图；
* 租户：列表、详情、手工开通、停用/启用、会话上限、默认套餐；
* 成员：查看与修改角色/状态/资料、重置密码（强制下次改密并踢下线）；
* 权益：授予/取消订阅、调整套餐配额（可预约生效）、租户级覆盖；
* 公告：**A 端发布、B 端接收**；发布支持全体或指定租户、立即或预约生效、草稿，
  修改与删除支持同样范围；平台账号统一拥有完整权限；B 端切换页面与每 60 秒刷新一次
  已生效公告；
* 设置：切换「默认开启测试模式」与「开启测试模式」，并展示当前实际验证码模式；
  正式服务下 B 端自助开通/降级会被拒绝（见 [4.5](#45-测试模式与正式服务)）；
* 我的：平台账号可修改昵称、头像、邮箱、组织名称与密码（点击左上角头像进入）；
* 界面：侧栏可拖拽调宽、上浮气泡、浅色/深色/随机主题与头像点击动效，与 B 端一致。

### 5.2 权限与边界

* 读操作：平台租户内任意有效会话；
* 写操作：平台登录 + CSRF；平台租户内账号在启动时统一为 `OWNER`，
  新注册账号也直接创建为 `OWNER`，因此套餐、租户与公告操作不再需要逐级授权；
* 企业租户的账号、Cookie、CSRF 令牌在平台接口一律无效；
* 修改成员时保留「至少一个可用所有者」约束，防止企业被永久锁死。

### 5.3 构建级隔离

```powershell
# 企业交付包（不含 /root）
powershell -File scripts/build-exe.ps1 -Edition business

# 自留 B+A 包（默认）
powershell -File scripts/build-exe.ps1 -Edition internal

# Linux
bash scripts/build-elf.sh --edition business
```

构建脚本会把版本写入产物内部的 `edition.txt`，运行时只读打包资源：

* `business`：不挂载平台路由、不构建/不打包 root-console，PyInstaller 排除
  `app.api.platform` 与 `app.services.platform`；
* `internal`：额外挂载 `/root` 与平台接口。

**为什么不用运行时开关**：环境变量可被目标机改写；构建元数据不会。企业构建即使把
`TRUESIGHT_AUTH__REQUIRE_LOGIN` 改回 `false`，`auth_enforced` 仍为真，管理接口必须登录。

## 六、接口速查

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/auth/status` | 是否已具备账号（供前端决定默认落在登录/注册）、是否已登录、构建版本 |
| POST | `/api/v1/auth/setup` | 受控初始化（接口保留；管理后台不再展示入口，受构建与开关限制） |
| POST | `/api/v1/auth/register` | 自助注册（默认开启） |
| POST | `/api/v1/auth/verification` | 发送找回密码验证码（邮箱/手机） |
| POST | `/api/v1/auth/recover` | 验证码重置密码 |
| POST | `/api/v1/auth/login` | 登录并写 HttpOnly Cookie |
| POST | `/api/v1/auth/logout` | 撤销当前会话 |
| GET | `/api/v1/auth/me` | 当前主体 |
| POST | `/api/v1/auth/password` | 自助改密（需 CSRF） |
| GET/POST | `/api/v1/admin/users` | 成员列表 / 新增 |
| PATCH | `/api/v1/admin/users/{id}` | 修改角色/状态/重置密码 |
| GET | `/api/v1/admin/subscription` | 权益、套餐、时长与历史 |
| POST | `/api/v1/admin/subscription` | 开通/续期 |
| POST | `/api/v1/admin/subscription/cancel` | 取消当前订阅 |
| GET | `/api/v1/admin/announcements` | 当前生效公告 |
| GET | `/root/api/v1/platform/overview` | 平台总览 |
| GET/POST | `/root/api/v1/platform/tenants` | 租户列表 / 手工开通 |
| PATCH | `/root/api/v1/platform/tenants/{id}` | 修改租户 |
| POST | `/root/api/v1/platform/tenants/{id}/subscription` | 授予/续期 |
| POST | `/root/api/v1/platform/tenants/{id}/subscription/cancel` | 取消 |
| POST | `/root/api/v1/platform/tenants/{id}/overrides` | 租户权益覆盖 |
| PATCH | `/root/api/v1/platform/tenants/{id}/users/{uid}` | 修改企业成员 |
| GET | `/root/api/v1/platform/plans` | 套餐列表（含内部） |
| PATCH | `/root/api/v1/platform/plans/{code}` | 调整套餐权益（可预约） |
| GET/POST | `/root/api/v1/platform/announcements` | 公告列表 / 发布 |
| PATCH/DELETE | `/root/api/v1/platform/announcements/{id}` | 修改 / 删除 |

错误码：`auth_failed`（401）、`account_locked`（429）、`csrf_invalid`（403）、
`forbidden`（403）、`tenant_suspended`（403）、`quota_exceeded`（403）。

## 七、迁移与运维

1. 升级数据库：`cd server; .\.venv\Scripts\alembic.exe upgrade head`；
2. 启动时会幂等创建默认租户、默认套餐与（internal）平台租户；
3. 内部构建首次启动后访问 `/admin`，没有账号时直接走「注册」；
4. 企业交付包不展示初始化入口，建议由服务方预置企业 owner 账号，
   或临时开启 `allow_bootstrap` 调用受控初始化接口；
5. A 端管理员通过环境变量提供，**不要**把密码写进仓库或镜像层。

## 八、明确边界（未实现 / 降级）

* **支付、发票、退款**：未接入。订阅页只开通权益，来源标记 `self_service`；
  真实收款属于外部流程，界面不假装扣费。
* **业务数据全量租户化**：本期完成账号、会话、设置、订阅、公告的租户边界；
  命中、资产、名单等检测数据仍是单库共享表，托管多企业隔离需要继续给这些表加
  `tenant_id` 并强制作用域（已在二期后续清单中，不在本期假装完成）。
* **多实例配额锁**：当前为单进程锁；多实例部署需数据库行锁/唯一约束。
* **邮件/短信通道**：验证码框架已就绪（`app/services/verification.py`），但真实发送渠道
  尚未接入；测试模式下 `stub` 任意验证码通过，关闭测试模式后会强制 strict，
  上线前必须先接入发送渠道（A 端设置页会对此组合告警）。
