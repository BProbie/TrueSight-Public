# 数据模型与隐私边界

这一篇回答两个问题：**数据存在哪、长什么样**，以及**哪一条数据是敏感的、它被怎样保护**。

## 一、表结构总览

| 分组 | 表 | 用途 | 敏感度 |
| --- | --- | --- | --- |
| 配置 | `settings` | 界面可改参数的持久化覆盖（键 + 值 + 作用域） | 低 |
| 配置 | `protected_assets` | 受保护资产（同时是白名单成员与品牌基准） | 低 |
| 配置 | `list_entries` | 黑白名单与词典集条目（唯一键：类别+形态+值） | 低 |
| 配置 | `llm_providers` | 模型供应商；**密钥为本地 Fernet 密文** | **高** |
| 检测 | `tasks` | 后台任务执行记录（状态、执行/跳过步骤、错误码、明细） | 低 |
| 检测 | `findings` | 命中记录（去重键 = `sha256("domain:" + 域名)`） | 中 |
| 检测 | `finding_evidences` | 证据索引行（相对路径 + SHA-256 + 采集上下文） | 中 |
| 交互 | `report_submissions` | 人工举报投稿（**只存举报者标识的带盐哈希**） | 中 |
| 交互 | `abuse_reports` | 对外举报留痕（通道、状态、请求体、响应摘要） | 中 |
| 运维 | `audit_logs` | 管理操作审计（动作、目标、操作者、**客户端标识哈希**） | 中 |
| 公开 | `dashboard_events` | **公网可读的脱敏投影表**（不含证据、注册人、精确 IP） | 低（可公开） |

## 二、关键字段与设计意图

### `findings`（命中记录）

| 字段 | 说明 |
| --- | --- |
| `fingerprint` | 去重键，唯一约束。同一个仿冒域名无论被多少条路径发现（DGA 扫描、用户举报、goto 拦截、情报源），都汇聚成同一条 |
| `source` | 首次发现来源；**重扫不改写它**（`upsert(source=None)` 表示保持原样），否则「谁先发现」会被永久抹掉 |
| `score` / `score_factors` / `rationale` | 评分与逐层因子、人可读理由 —— 可解释性的数据基础 |
| `summary` 类字段（`whois_summary` / `dns_summary` / `tls_summary` / `http_summary`） | **脱敏摘要**，不含原文 |
| `report_markdown` | 研判报告正文（含模型生成文本，**只作人可读产物，不回流判定**） |
| 状态机 | `new → pending_review → confirmed → reported → resolved`，另有 `dismissed`；**只升不降**（低分再次发现不会把已确认的结论覆盖掉） |

### `finding_evidences`（证据索引）

文件本体在 `data/evidence/<fingerprint>/`，**库里只存索引**：

| 字段 | 说明 |
| --- | --- |
| `relative_path` | 相对证据目录的路径，读取时做越界校验 |
| `sha256` | 内容哈希，用于校验完整性（改动即被发现） |
| `captured_at` | UTC 采集时间 |
| `context` | 采集上下文（HTTP 状态、最终 URL、体积、是否截断、UA 等），**不含 IP 与请求头原文** |

同一条命中重复取证时：内容一致的证据**不重复建索引行**（按 `(kind, sha256)` 去重），
清单含生成时间因此每次都会新写一份 —— 这样时间线完整而数据不膨胀。

## 三、隐私边界：谁看不到什么

| 数据 | 本地端 | 公网端 | 说明 |
| --- | --- | --- | --- |
| 原始证据（HTML/文本/证书） | ✅ 文件本体 | ❌ 完全不落 | 公网端只拿脱敏投影 |
| WHOIS 注册人 | ✅ 摘要 | ❌ | 摘要也不含注册人原文 |
| 举报者 IP | ❌ 只存带盐哈希 | ❌ | 用于防刷与去重，不能反推身份 |
| 管理操作者 IP | ❌ 只存带盐哈希 | — | 审计里只展示哈希前缀 |
| 模型 API 密钥 | ✅ 密文（可解密） | ❌ | 接口只回遮蔽值 `sk-***xxxx` |
| 页面正文 | ✅（证据文件） | ❌ | 公网端只有聚合统计 |

三条实现细节值得单独点出：

1. **公网端看不到原文，是因为它压根不读那些表**：`public` 模式只消费
   `dashboard_events`（由本地端单向投影写入），而不是「读到了但不返回」；
2. **`SiteAssessment` 刻意不含页面原文**：判定链路只带走脱敏结论，
   因此「判定」这个每秒都可能发生的动作不会把网页内容扩散到各处；需要原文的取证是
   独立的第二步；
3. **密钥只进不出**：管理后台写入密钥后，任何接口都不会读回明文或密文；
   「已配置（无法解密）」这个文案本身就是降级说明，而不是错误。

## 四、证据链为什么能作为维权附件

电子证据要站得住，需要三件事，工程实现一一对应：

| 法律要求 | 实现 |
| --- | --- |
| 原始性 | 按类型分别留存原文（HTML / 文本 / 证书 / JSON），不做有损转换；并记录原始字符集声明与截断状态 |
| 完整性 | 每件证据记录 SHA-256；提供校验方法；清单本身也落盘并计入哈希 |
| 时间可核验 | 落盘即记录 UTC 采集时间，并写入 JSON 清单（`truesight.evidence.manifest/1`） |

清单结构：

```json
{
  "schema": "truesight.evidence.manifest/1",
  "fingerprint": "…",
  "domain": "example-bank-login.top",
  "generated_at": "2026-10-20T11:44:12Z",
  "artifact_count": 4,
  "total_bytes": 41233,
  "artifacts": [{"kind": "html", "relative_path": "…", "sha256": "…", "size_bytes": 24512,
                 "media_type": "text/html", "captured_at": "…", "context": {…}}],
  "extra": {"finding_id": 1}
}
```

**已知取舍**：HTML 证据保存的是解码后的 UTF-8 文本（抓取器只回传解码结果），
原始字节与字符集声明记录在索引行的 `context` 里 —— 这是为「零额外重依赖」付出的代价，
文档里如实写明而不是掩盖。

## 五、数据落盘位置与备份

| 路径 | 内容 | 备份要点 |
| --- | --- | --- |
| `data/db/truesight.db` | 全部业务表 | 与主密钥一起备份 |
| `data/evidence/` | 证据链文件 | 体积可增长；可按 `findings` 生命周期归档 |
| `data/logs/` | 结构化运行日志 | 已脱敏，可不长期保留 |

**主密钥丢失的后果**：已入库的模型密钥无法解密（列表显示「已配置（无法解密）」，
需要重新录入）；命中、证据、审计数据本身不受影响。

## 六、数据库迁移

* 开发与单机：`local` 模式下启动即建表（`create_all`）；
* 生产：用 Alembic —— `alembic upgrade head`（配置见 `server/alembic/` 与 `alembic.ini`）；
* 枚举一律以**成员名**存字符串（非原生 ENUM），扩值时不需要 `ALTER TYPE`；
* 时间列统一「无时区的 UTC」，避免本地时区漂移导致的过期判断错误。
